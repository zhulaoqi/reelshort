# ReelShort CPS

两项能力，都先按用户给的邮箱匹配 `config/accounts.json` 里的账号并登录：

| 用户想要 | 用哪个 | 输出 |
|---|---|---|
| 某剧/某语言的推广链接 | `scripts/reelshort.py` | 按剧名分开的 App推广链接、资源推广链接 |
| 某邮箱某时间段的收益详情 | `scripts/earnings.py`（见文末“收益导出”） | `.xlsx` 文件 + 摘要 |

# 一、推广链接获取

输入：账号 + 可选的 剧名 / 语言 / 排序 / 个数。输出：按剧名分开的 App推广链接、资源推广链接。

## 工作流

1. **确定账号**。用户给的邮箱 / 前缀 / 别名 / 公司名都传给 `--account`，由脚本去配置里模糊命中。
   - 没给账号：先问用户用哪个账号（可用 `--list-accounts` 列出，不含密码）。
   - 脚本退出码 `2` = 需要用户澄清（账号命中多个、语言无法识别等），把 stderr 里的提示原样转述并让用户选，**不要自己猜**。
2. **提取检索条件**（全部可选，可组合）：
   - 剧名 → `--title`（可重复，或逗号分隔）
   - 语言 → `--lang`（口语即可：日文/日语/日本/jp/繁体/台湾…，可多个）
   - 排序 → `--sort`（`time` 最新添加，默认；`money` 近30天充值金额高→低。口语：最新/最近→time，热门/收益/充值/排行→money）
   - 个数 → `--count`（默认 10，上限 200；多语言/多剧名时每个组合各取这么多）
3. **运行脚本**（在 skill 目录下，或用绝对路径）：

```bash
python3 scripts/reelshort.py --account <账号> [--title 剧名] [--lang 语言] [--sort time|money] [--count N] [--offset K]
```

4. **原样输出脚本结果**（脚本输出的就是 Markdown 卡片，直接作为回复正文，**不要再包进代码块**，也不加解释、不改动卡片内容）。

## 超长截断与分批（脚本自动处理）

- 单次最多展示 15 部（`config/aliases.json` 的 `page_size`，`--page-size` 可调，上限 30），另有 16000 字符兜底；超出的截断，末尾提示“共 N 部，本次展示第 a–b 部，还剩 M 部（offset=b）”。
- 用户说“继续 / 下一批 / 更多”时，**沿用上一次完全相同的参数**，只加 `--offset <提示里的 offset>`，再原样输出。
- 详情和短链只对本批展示的剧去请求，所以 `--count 200` 也不会一次拉几百条。

## 多个账号

一个账号一次调用，**逐个账号依次运行、依次回复**（每个账号的结果单独成段，先完成的先返回），不要合并成一张表。用户说“全部账号”时先 `--list-accounts` 再逐个跑。

## 输出格式（脚本已按此输出，渲染后每部剧是一张卡片）

~~~markdown
## 👤 jenhu@isummerads.com · 共 1 部

---

**1. 千億の御曹司と極秘結婚した愛妻**　`日语`
```
# App推广链接
https://reelslink.com/cps/GjGMAS
# App截取信息结果
&deep_link_value=...&af_dp=cmsvictor%3A%2F%2F
# 资源推广链接
https://reelslink.com/cps/RbwC00
# 资源截取信息结果
&deep_link_value=...&af_dp=cmsvictor%3A%2F%2F
```
~~~

- 一部剧 = 一个标题行（加粗剧名 + 语言标签）+ **一个整体代码块**，标签是代码块里的 `#` 注释行，便于整块一键复制。
- 每部剧各有自己的两组链接（不同剧的链接不同，不可复用）。“推广链接”= 接口返回的 `reelslink.com` 短链；“截取信息结果”= 访问该短链后 302 跳转地址中 `&deep_link_value=…&af_dp=…` 的整段，两者一一对应。
- 某条失败时该剧卡片末尾会多一行 `> ⚠ 原因`，其余照常输出；无结果时输出 `> 未找到符合条件的短剧。`

## 模糊输入处理

- **账号**：精确邮箱 > 邮箱前缀 > 别名 > 子串（≥3 字符）。多命中（如 `cloudmobi` 同时是两个账号）→ 退出码 2，让用户选。
- **语言**：`config/aliases.json` 的 `languages` 做归类，取“被输入包含的最长别名”（“繁体中文”不会误判成“中文”）。认不出 → 退出码 2 并列出可选语言。
- **排序**：同上，`sorts` 归类；没说就用 `time`。
- **剧名**：服务端关键词搜索，且是按该语言的剧名匹配。结果为空时脚本会自动去标点重试一次；仍为空则告诉用户“没找到”，并建议缩短关键词、换语言或确认原名，不要编造链接。
- 用户说“XX语的剧”但没给剧名 → 就是只按语言 + 排序 + 个数取。
- 用户的新说法没被识别 → 往 `config/aliases.json` 对应 `aliases` 里加一个词即可。

## 配置维护

- 账号：`config/accounts.json`（`email` / `password` / `aliases`）。新增账号按同结构追加；公司名等多账号共有的词**不要**放进 aliases，保留歧义确认。
- 该文件含明文密码，已通过 `.gitignore` 排除；模板见 `config/accounts.example.json`。

## 退出码

`0` 成功 · `1` 网络/接口错误（已自动重试 3 次） · `2` 需要用户澄清 · `3` 登录失败（账号或密码有误，转述 stderr）。两个脚本通用。

# 二、收益导出（短剧预估收益）

用户问“某邮箱某时间段的收益 / 收益明细 / 下载收益”时用。**只导出短剧预估收益**（网站 `我的收益 → 短剧预估收益` 页的“下载”按钮，小说/分销收益不做）。

```bash
python3 scripts/earnings.py --account <账号> [--date 日期] [--title 剧名] [--lang 语言] [--ptype 推广方式] [--promotion-value 链接或口令] [--has-order]
```

| 用户说的 | 参数 | 说明 |
|---|---|---|
| 时间段 | `--date`（或 `--start` + `--end`） | 口语直接传：昨天、今天、前天、最近7天、近一个月、上周、本周、上月、本月、10月、10月1日到10月7日、2026-10-01~2026-10-07、10/05。**没说时间默认昨天** |
| 某部剧 | `--title`（可重复） | 先按剧名搜出 book_ids 再筛；`--lang` 只用来缩小剧名搜索，**不能单独按语言筛收益**（会提示补剧名） |
| 推广方式 | `--ptype` | 资源链接 / App链接 / 口令 / 内嵌播放器 |
| 某条链接或口令 | `--promotion-value` | 最长 100 字符 |
| 只看有订单的 | `--has-order` | 对应页面“是否包含订单数据：是” |

要点：

- **日期按平台时区（美国洛杉矶）**，不是北京时间。“昨天 / 最近N天”以洛杉矶的昨天为终点；“今天”可查。结束日超过平台今天会自动截到今天；区间超过 30 天会提示（页面只支持近 30 天）。
- 日期无法识别 → 退出码 2，把提示转述给用户并让其补充，不要猜。
- 导出的文件 = 网站下载的 xlsx，含两个工作表：① 按日期的汇总明细（日期/资源名称/推广方式/推广信息/订单数/预估收益）② 订单明细（订单号/订单时间/订单金额）。导出的是**全部**符合条件的数据，不分页。
- 文件**只临时落盘**（不进项目目录），文件名 `Drama_Estimated_Earnings_{起}_{止}_{邮箱前缀}[_筛选后缀].xlsx`；发送完就删，不长期占磁盘（见下方“发送后清理”）。
- **输出目录要在聊天插件允许发送附件的白名单内**，否则插件会静默拦截（飞书报 `LocalMediaAccessError: path-not-allowed`，用户只收到文字没有文件）。脚本默认按优先级自动选：环境变量 `REELSHORT_OUT_DIR` → `/tmp/openclaw`（存在即用）→ 系统临时目录，文件放在其下的 `reelshort_earnings/`。部署时若白名单是别的目录（如 agent 工作区），设置环境变量 `REELSHORT_OUT_DIR=<白名单目录>` 即可，不用改代码。
- 没有数据时不生成文件，输出 `> 该条件下没有收益数据。`

**输出**：

收益导出的回复**只有两样东西**，缺一不可，也不要多：摘要 + xlsx 文件。

**严禁额外内容**（成功时用户不需要看到任何过程信息）：
- 不要在摘要前加自己的标题行（如“📊 xxx · 短剧预估收益（日期）”），摘要自带标题；
- 不要在摘要后加“📎 附件：文件名（已发送）”“无新报错，附件发送成功，请查收”“已为你导出”等确认/说明文字；
- 不要提及路径、临时目录、清理动作；
- 只有**出错或异常**（发送被拦截、无法发文件、日期没识别等）才说话，且只说问题与下一步。

1. **摘要**：原样发送脚本 stdout（Markdown，不要包代码块，不要改写、不要自己加任何内容）。例：

   ~~~markdown
   ## 📊 jenhu@isummerads.com · 短剧预估收益

   `2026-10-05 ~ 2026-10-11（洛杉矶时间）`　`推广方式: App推广链接`

   推广资源 4 个　·　订单 17 笔　·　预估收益 $0.00　·　明细 10 行
   ~~~

2. **文件**：紧接着把 xlsx **作为文件本身**发出去（文件卡片自带文件名，不需要任何文字说明）。文件的绝对路径在脚本 **stderr** 的一行 `ATTACH_FILE=<路径>` 里，这是给你调用“发送文件/附件”工具用的内部信息：
   - 路径**不属于**要展示给用户的内容：不要把路径或文件名当文字发出去，也不要把 xlsx 内容转成文字/表格。
   - 只有发送工具真实返回成功，才算发送完成；**发送可能被插件静默拦截**，所以要看工具的返回/日志，不能因为“没报错”就认定成功。
   - 若被拦截（如 `path-not-allowed`）：用 `--out-dir <插件允许的目录>` 重新导出（该目录建议以 `reelshort_earnings` 命名，便于过期自动清理）后再发；原来的文件用 `--cleanup` 清掉。

没有数据时只发摘要里的 `> 该条件下没有收益数据。`，没有文件消息。

若当前环境确实没有发送文件的能力：如实告诉用户“无法发送文件”及原因，保留文件、不要清理，并询问是否改存到指定目录（`--out-dir`）。

**发送后清理（必做）**：文件消息**发送成功后立刻**删除，避免磁盘堆积：

```bash
python3 scripts/earnings.py --cleanup <ATTACH_FILE 的路径>
```

- 只有确认**附件已发送成功**才清理；发送失败就保留并重试，仍失败则如实告知用户。
- `--cleanup` 只会删本工具生成的 `Drama_Estimated_Earnings_*.xlsx`，其他文件会拒绝。
- 兜底：即使忘了清理，每次再运行导出时，临时目录里超过 60 分钟的旧文件也会被自动删除。
- 用户明确要求“保存到某目录”时才加 `--out-dir`，该目录不会被自动清理，也不要对它执行 `--cleanup`。

多账号同样一个账号一次调用、逐个返回（每个账号的文件各自发送、各自清理）。

接口细节与排错见 [reference.md](reference.md)。
